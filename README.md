# Manufacturing Production Delay Prediction AI

An end-to-end machine learning project that predicts, for a manufacturing line shift:

- **Delay risk**: Low / Medium / High
- **Expected production quantity** and **target achievement %**
- A **possible bottleneck** (downtime, changeover or slow cycle time) and a **recommended action**

It contains data preprocessing, model training and evaluation, a FastAPI backend, a Streamlit demo UI and automated tests.

> **Synthetic data warning.** The dataset is synthetic. Every metric in this repository comes from synthetic data and is **not** a real-factory result. Before any real use, validate the models on the factory's own production records.

## Quick start

Requires Python 3.10+.

**Windows**
```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
run_project.bat
```

**Linux / macOS**
```
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./run_project.sh
```

The script preprocesses the data, trains the models, evaluates them, runs the tests, starts the API on http://localhost:8000/docs and opens the UI (http://localhost:8501).

Run the steps yourself:
```
python 03_Data_Preprocessing/preprocess.py
python 04_Training/train_model.py
python 04_Training/evaluate_model.py
uvicorn main:app --app-dir 06_API --port 8000        # API
streamlit run 07_UI/app.py                           # UI (second terminal)
python -m pytest 09_Tests -q                         # tests
```
Trained models are not stored in the repository; `train_model.py` creates them in `05_Models/`.

## How it works

Two models are trained so that no information from the future leaks in:

| Model | Uses | Meaning |
|---|---|---|
| `plan` | Only information known before the shift (plan, line type, equipment condition, planned headcount) | Pre-shift risk estimate |
| `shift` | `plan` inputs plus downtime, actual cycle time, operators present, changeover time, downtime events | Current-shift estimate |

- **Targets.** `achievement_pct = actual / planned x 100`. `delay_risk` is High below 60%, Medium from 60% to 75%, Low at 75% or more. These thresholds are an assumption chosen for this dataset (no shift reaches 100%, the mean is 65%); change them in `config.py`.
- **Quantity.** Predicted achievement % x planned quantity.
- **No leakage.** Actual quantities, OEE, throughput and other target-derived columns are never inputs (`config.py`, `LEAKAGE_COLUMNS`; checked by a test).
- **Split.** Chronological by shift date: oldest 70% train, next 15% validation (model selection), newest 15% test.
- **Models compared.** Logistic Regression, Random Forest and XGBoost (scikit-learn HistGradientBoosting is used instead if `xgboost` is not installed).
- **Bottleneck and action.** Rule-based: the largest of downtime share, changeover share and cycle-time slowdown (shown only if at least 5%). It names a type of loss, not a specific machine.

## Dataset

Hugging Face `xpertsystems/mfg005-sample`, file `mfg005_synthetic_line_performance.csv` (included in `02_Dataset/raw/`): 3,000 shifts, 118 columns, 2020-01-01 to 2024-12-30, 36 lines, synthetic. **Check the licence on the dataset page before redistributing it.** Details: `01_Reference/dataset_source.md`, `02_Dataset/data_dictionary.md`.

## Results

Held-out test set: newest 15%, 450 shifts (2024-04-12 to 2024-12-30). Generated by `evaluate_model.py` (files in `08_Results/`). The committed numbers were produced with HistGradientBoosting in place of XGBoost; retraining with `xgboost` installed can change them slightly.

| | Pre-shift `plan` | Current-shift `shift` |
|---|---|---|
| Selected classifier | Random Forest | Logistic Regression |
| Accuracy | 0.44 | 0.978 |
| Macro precision / recall / F1 | 0.44 / 0.45 / 0.44 | 0.976 / 0.980 / 0.978 |
| Majority-class baseline accuracy | 0.40 | 0.40 |
| Achievement % MAE (baseline 11.8) | 10.6 pts | 0.70 pts |
| Quantity MAE (baseline 97 units) | 80 units | 5.9 units |

How to read this:
- The `plan` model is barely better than guessing. Planning data alone carries little signal in this dataset.
- The `shift` model is very accurate because, in this synthetic data, output follows downtime and cycle time almost mechanically. Real factories are noisier, so expect lower numbers.

## API

| Endpoint | Description |
|---|---|
| `GET /health` | Service status and whether models are loaded |
| `GET /model-info` | Model metadata and test metrics |
| `POST /predict` | Predict one shift (`mode`: `plan` or `shift`) |
| `POST /upload-csv` | Validate a CSV and run batch predictions |
| `GET /sample-data` | Sample rows or the sample CSV |

Swagger UI at `/docs`. Request/response examples: `10_Documentation/API_DOCUMENTATION.md`.

## UI

A single-page Streamlit demo: choose an example shift (Good / Average / Bad) or enter planned quantity, shift duration, planned and actual cycle time, downtime and changeover time, then click **Predict**. The output shows delay risk, predicted production vs plan, target achievement %, possible bottleneck and recommended action. Other model inputs use fixed typical values in the demo; the API accepts all of them.

## Limitations

- Synthetic data; real-factory validation is required before any deployment.
- Pre-shift prediction is weak.
- The bottleneck is a rule-based reading of the entered values. It does not identify a machine.
- Operator headcount shows no relationship with output in this data, so it is not used in bottleneck reasoning.
- No "current production quantity" input: the data has no in-shift partial counts.
- Risk thresholds are assumptions; class probabilities are not calibrated.
- Future multi-day forecasting is not implemented.
- No savings claims: those need a fair before/after comparison on real data.
